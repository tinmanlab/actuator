02 / AN EXECUTABLE EXAMPLE, NOT PSEUDOCODE

Run 0.8 simulated seconds from C++.

This example is built as qdd_live_example and run by CTest. It uses the exact facade compiled to WASM. The output angle should be within 0.03 rad of 0.4 rad and the fault code should remain zero.

// Host/SIL example of the SAME facade exported to WebAssembly. No hardware I/O.
#include "../web/live.h"
#include <cmath>
#include <iostream>
int main() {
 if (!lab_reset(0) || !lab_set(0, 4) || !lab_set(1, 0.4)) return 1;
 // reset(0) chooses PI; set(0,4) chooses impedance; set(1,...) is output radians.
 for (int i=0; i<160; ++i) if (lab_step(100)!=100) return 2;
 // 16,000 ticks * 50 us = 0.8 simulated seconds; not wall-clock pacing.
 const double position=lab_get(1), current=lab_get(4);
 std::cout << "output_rad=" << position << ", iq_A=" << current << '\n';
 if (lab_get(12)!=0 || std::abs(position-0.4)>0.03) return 3;
 return 0;
}

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/qdd_live_example
ctest --test-dir build --output-on-failure

Source: examples/live_api.cpp. Python is needed at build time for geometry-derived browser stop bounds. It is not in the C++ simulation loop. A core-only build remains available with -DQDD_HOST=OFF.

03 / BROWSER + HOST EXPERIMENT FACADE

web/live.h: four exported functions.

int    lab_reset(int predictive);        // 0 = PI, 1 = relaxed predictive
int    lab_set(int field, double value); // validated command, 1 accepted / 0 rejected
int    lab_step(int ticks);              // n ticks at 50 us; n on success, 0 on failure
double lab_get(int field);              // numeric snapshot; invalid field returns NaN

lab_reset returns 1 on success and 0 on failure. Positive stepping requests are bounded to 10,000 ticks per call; zero ticks is a no-op. This is a single-instance, heap-using, serialized host facade, not the embedded C11 interface. Reset discards plant, temperature, energy and fault history. Fatal integration errors inhibit further stepping until reset.

04 / NO BACKEND, NO REST SERVER

The Worker is the browser control boundary.

worker.js instantiates Emscripten's createQdd() module and calls core._lab_* exports. The UI sends messages; it does not call Drive directly and does not need an API key.

// Send to your Worker instance; the existing app already creates one.
worker.postMessage({type: 'set', key: 1, value: 0.7});
worker.postMessage({type: 'run', value: true});
worker.postMessage({type: 'set', key: 7, value: 4}); // 120 ms load pulse
worker.postMessage({type: 'run', value: false});
worker.postMessage({type: 'step'});                 // paused: 20 ticks = 1 ms
MessageEffect / reply
resetNew paused experiment. Optional scenario, algorithm, values. Reply: reset + row.
setValidated command change. It is not a telemetry sample.
run / stepToggle integration, or advance one millisecond while paused.
rate0.25 or 1 target wall-time rate; fixed physics timestep is unchanged.
samplesReply with rows of plant state and controller outputs.
rejectedStop activation intersects the solid obstacle. Undo the checkbox, keep the experiment alive, move clear or reset.
errorEngine/validation failure; show it and stop rather than animating stale state.

Do not infer real-time deadlines from setInterval: the browser may throttle or fall behind. Simulated time comes from the C++ tick count. Hiding the document pauses the UI's run request.

05 / THE REUSABLE LOW-LEVEL CONTROLLER

Drive::tick(Measurement, Command)

Drive owns the state machine, sensor-offset calibration, outer-loop state, current reference limits, current algorithm and modulation. Each tick returns DriveOutput: duties, estimated dq current, limited references, voltage, gate enable, state, fault and saturation flags. It does not advance the physical plant.

class CurrentAlgorithm {
public:
  virtual ~CurrentAlgorithm() = default;
  virtual DQ voltage(DQ reference, const CurrentFeedback&, float dt) noexcept = 0;
  virtual void track(DQ requested, DQ applied, float dt) noexcept = 0;
  virtual void reset() noexcept = 0;
};

voltage() requests a voltage vector; track() receives the final vector after limiting for anti-windup; reset() clears algorithm state. Drive::use_algorithm() accepts a caller-owned instance only while Disabled or Ready. The algorithm must outlive the Drive and all calls must be serialized. Do not allocate, block, log, or access hardware inside the control method.

The allocation-free C11 boundary is different

qdd/c_api.h uses a caller-owned, zero-initialized qdd_context with 1024 bytes of aligned storage, one per motor. qdd_default_config → qdd_init → qdd_tick → qdd_destroy is the lifecycle. Do not copy an initialized context or call it concurrently.

qdd_init returns 0 on success, −1 for invalid pointers/storage, −2 for invalid configuration. qdd_tick can return 0 while its output contains a latched motor fault: inspect out.fault and out.gate_enable, not only the return value. Calibration, valid measurements, arming and coherent sample ages are caller responsibilities. Tested C11 caller →

STM32 is still a port contract

BoardPort / control_irq requires coherent ADC/encoder snapshots, hardware BREAK status, commissioning approval, gate-off and atomic PWM/gate commit. It does not configure TIM1, ADC, DMA, MOSFETs, CAN-FD, or a real board. The host mock test is not hardware execution evidence.

06 / A PHYSICS ENGINE, NOT A POSE PLAYER

MuJoCo owns positions, velocities and both inertias.

external.h is host-only C ABI v1. Create a handle with qdd_external_create(switched, predictive), query qdd_external_period(), call qdd_external_tick() and finally destroy the handle. Creation may return null; tick returns 0 on success, −1 on invalid/fatal input.

MuJoCo qpos/qvel → QddExternalInput C++: sensor frame → FOC → bridge + PMSM electrical substeps QddExternalOutput: average rotor torque + output gearbox torque MuJoCo qfrc_applied += those torques → mj_step → next qpos/qvel

Internal mechanical integration is disabled for both inertias in this mode. C++ still computes reciprocal gearbox reaction, rotor friction, electrical current, bus and thermal state. MuJoCo owns output friction, gravity and contact. Imposing commanded positions on qpos after stepping would destroy that closed loop; the bridge does not do that.

The exchange interval is 50 μs with explicit torque holds. More mechanical substeps refine MuJoCo integration but not the exchange rate. Previous contact/impact refinement results therefore do not establish coupling-rate convergence. Runner · ctypes layout.

Use a fresh output directory for every evidence run. The web build needs Emscripten; recording needs ffmpeg and an available graphics backend.
